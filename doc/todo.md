# 今後の課題

実機と突き合わせて「合っている」ところまでは来た（発音指示 2851 件一致、振幅
88.7% が 10% 以内）。ここから先に残っているものを、**直す順**に並べてある。

順番の理由は 3 つ。(1) 直したことで音が変わったと気づける仕組みが先に要る。
(2) 遅れの半分は音源ではなく外の配管なので、安い手から取る。(3) 速さの話は
待ち時間の下限を決めるので、詰めるなら最後にまとめて。

---

## やる順

### 1. `make test` と基準の波形をこのリポジトリに置く

いま回帰試験が**別のリポジトリに散っている**。基準の WAV と MAME 側の改造が
`MU2000` 側にあり、`statetest` と `verify` はあるが Makefile に試験の的が無い。

この状態では、以下のどれを直しても「音が変わったことに気づけない」。
design.md が移植で一番怖いと書いた事態そのもの。

やること:

* 数本の基準 WAV（短いロングトーン数種 + 実曲の一部）をここに置く
* `make test` で `render` → `compare_wav.py` → `statetest` まで一息に回す
* 判定は包絡線だけに頼らない。keyon のサンプル番地と回数も見る（design.md）

### 2. 単体 exe の MIDI をサンプル単位にし、デバイスの本来の形式で開く

VST3 の経路は既にサンプル単位で、`process` がイベントの `sampleOffset` で
ブロックを割って流し込んでいる（`src/vst3/plugin.cpp:640`）。**単体 exe だけが
遅れている。**

| 原因 | 量 | 場所 |
|---|---|---|
| MIDI をブロックの頭でまとめて流す | 0〜30ms（平均 15ms） | `src/ui/driver.h:39` |
| WASAPI 共有モードの既定 30ms | 30ms | `src/gui.cpp:682`, `src/live.cpp:362` |
| `AUTOCONVERTPCM` で Windows が 44100→48000 を挟む | 数 ms + 音質 | `src/ui/audio_out.cpp:111` |

手は 3 つ。上から安い。

1. midiIn のコールバックで QPC の時刻を付け、ブロックの中の位置へ直して流す。
   VST3 でやっていることを単体側でもやるだけ。**平均 15ms 消える**
2. デバイスの形式のまま開き、変換は `engine` の sinc を使う
   （`src/vst3/engine.cpp` にあるものが単体側では使われていない）。
   Windows の変換とその溜めがまるごと無くなる
3. `IAudioClient3::InitializeSharedAudioStream` で共有モードのまま
   2.67〜10ms 周期にする。これは音源が小ブロックを落とさない速さである
   ことが前提なので、6 番と繋がっている

**実機との差を数字で出す**のも先にやる。`rec.exe <入力> out.wav <秒> --send
<番号> <midi>` で実機のノートオン→発音を録り、同じ MIDI を `render` に通して
先頭からの位置を比べれば、実機自身の遅れが出る。それを引いた残りが上乗せ分。

### 3. 積算器の丸めを変えて 30Hz 以下の残りを測る

30Hz 以下が 5.3% 残っている（実機 0.13%）。倍音は合っているので極の値は
6/256 前後で正しく、残りは別の何か——という読みの裏づけになる場所がある。

`src/mame/sound/swp30.cpp:2701` の `mixer_att`:

```cpp
return (sample - ((sample * (att & 0xf)) >> 4)) >> (att >> 4);
```

`>>` は負の側で −∞ へ落ちるので、**経路 1 本あたり平均 −0.5 LSB** 偏る。
`mixer_step` は入力が 0 の声を飛ばすので、偏りは**鳴っている声の数に比例**
する。つまり定数の直流ではなく、音符の出入りに合わせて動く 30Hz 以下の
成分になる。内側の `>>4` も同じ向きに効く。

確かめ方:

* 最近接（`(x + (1<<(n-1))) >> n`）と 0 方向（`x<0 ? -((-x)>>n) : x>>n`）の
  二通りを試し、137 秒の突き合わせを回す
* 振幅 ±0.5 LSB の話なので**倍音側はまず動かない**。直流だけが動くかを見る
* 無音時（全声 off）と発音時で別々に測れば、ミキサ由来か展開器・エンベロープ
  由来かが切り分かる

### 4. 起動状態のキャッシュと不揮発メモリの保存

**挿してから数秒鳴らない。** 起動の空回しを毎回やっている
（`src/vst3/engine.cpp:287`、最長 30 秒ぶん）。

**毎回工場出荷状態になる。** MAME は work RAM を NVRAM として保存している
（`src/mame/ymmu2000.cpp:348`）が、こちらは毎回全 0 から
（`src/mu2000.cpp:55`）。ユーティリティの設定もユーザ音色も残らない。

どちらも道具は揃っている（`save_state` / `load_state`）。ROM のハッシュを鍵に
して `%LOCALAPPDATA%` に貯め、次からはそれを読む。

ついでに**状態の blob が約 5MB** ある。サンプリング RAM 4MB を丸ごと入れて
いるため（`src/mu2000.cpp:753`）、DAW のプロジェクトに 1 台あたり 5MB 乗る。
0 の区間を畳むだけで実用上ほぼ消える。

### 5. VST3 のイベントバスを 2 本にする

イベント入力バスが 1 本 16ch しかない（`src/vst3/plugin.cpp:191`）。単体 exe
には A/B の 2 口があって**パート 1-32 が使える**のに、VST3 では 17-32 に
DAW から届かない（SysEx 経由だけ）。バスを 2 本にすれば揃う。

### 6. メモリバスをページテーブルにする

1 命令ごとに領域 4 つを線形に走査している。
`src/mame/cpu/sh2.cpp:264` → `mem_bus::read_word` → `src/compat/membus.h:130`
の `for (auto &r : m_regions)`。

design.md が「後で線形探索が問題になったらページテーブルに差し替える」と
書いた場所そのもので、CPU 使用率 38% の内訳で一番大きい候補。ここが軽く
なれば待ち時間の下限も下がる（2 番の 3 つめの前提）。

**先に内訳を測る。** CPU と SWP30 のどちらが重いのか分からないままなので、
`boot` に時間の内訳を出す口を付ける。

## 残りの課題

### 音の正しさ

| | |
|---|---|
| **8bit 圧縮サンプルの展開器が不正確** | MAME 自身が「乗算器はバグっていて負に偏るが正確な挙動は不明。スケーリングが 0 か非 0 かで結果が変わり、隠れた状態がある」と TODO に明記。ロングトーンで「ブーン」というノイズが乗る |
| **`sin-table.bin` が自作の近似** | `tools/dump/make_standins.py:53` で 1/4 波 sin を合成している。MEG の中の表なので、リバーブ・コーラス・バリエーション全部に効く。まず「効いているのか」を測る。表を意図的に壊して出力が変わるかを見れば影響の大きさが分かる。変わらないなら気にしなくていい |
| **LCD のフォントが実機と一致しない** | 代用品は Adafruit の 5x7 から起こしたもので、0x80 以上は全部空白にしてから推測した 4 字とレベルメータだけ描いている（`tools/dump/make_standins.py:36`）。記号が合わない。実機から撮るなら、全 256 コードを DDRAM へ書かせる小さなダンパを流して LCD を撮る手がある |
| MEG とレジスタ間の通信タイミングが未実装 | MAME の TODO（`src/mame/sound/swp30.cpp:21`）。鳴っている最中にエフェクトのパラメータを変えたときの挙動がずれる可能性。エディタ画面から触る用途で出る |
| MEG 命令の 7bit・LFO slot 9・slot b が未解明 | 同じ TODO。どの効果で出るかも不明 |
| 出力が 16bit 固定で、0 方向の整数除算 | `l * 32768 / DAC_FULL_SCALE`（`src/render.cpp:142` 他）。比較の基準にする波形が 16bit に丸められている。直流を追うなら float で出せたほうがいい |

### 実時間性・性能

| | |
|---|---|
| 小ブロックでの取りこぼしが未実測 | `m_late` を数えてはいる（`src/vst3/plugin.cpp:679`）が、何サンプル以下で落ちるかの数字が無い。128/256/512 で測る。落ちるなら「1 ブロック先に作って申告する」安全側の選択肢も要る |
| 複数挿しでスピンスレッドが増える | 1 台ごとにスレーブ用のスレッドが 20000 回空回りする（`src/mu2000.cpp:86`）。4 台挿すと回し待ちが 4 本。コア数で決めるか、台数で分け合う |

### 機能の穴

| | |
|---|---|
| **A/D 入力が無い** | ADC は 0 固定（`src/mu2000.cpp:540`）で、VST3 に音声入力バスも無い。A/D パート、入力へのインサーション、サンプリング、ボーカルハーモニーが使えない。入れると「MU2000 をエフェクタとして挿す」ができる。入口の MELI 線は未確定だが、`TO_SLAVE` が飛ばしているスレーブの 6 と 7 が空いている（`src/mu2000.cpp:723`）のは候補。試験信号を各線に入れて、A/D パートの設定で音量・パンが動く線を探せば決まる |
| SmartMedia 未実装 | 0xC00000 / 0xD00000 を受けていない。保存・読み込み・波形の取り込みができない |
| USB (M37640) 未実装 | 0xF80000。USB-MIDI とホストモードが使えない。IC5 の ROM も未吸い出し |
| 未マップ番地の読みが黙って 0 | `src/compat/membus.h:64`。0xD80000（コントラスト・レベル）や 0xE80000（デジタル出力）も含めて何も言わずに 0 が返る。記録する口が無いと「実は触っていた」に気づけない |

### 配布と体制

| | |
|---|---|
| CI が無い | `.github` が無い。ROM 無しでもビルドは通るので、それだけでも回す価値がある |
| Windows 専用 | `windows.h` を使うファイルが 19 本。音声・MIDI・窓・ファイル経路が全部 Win32。macOS/Linux と CLAP/AU をやるなら、早めに層を切ったほうが安い |
| 配布物が無い | 利用者に MSYS2 を建てさせている。ROM は同梱できないが exe は配れる |
