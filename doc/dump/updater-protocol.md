# MU2000 ファームウェア更新プロトコル（アップデータ解析メモ）

出典: `mu2r1_uw.zip`（MU2000 Extended Edition R1 アップデータ for Windows, 2002-07-05）の解析。
ソフトダンプ（自作コードを実機に送って波形 ROM を読み出す）を検討するための基礎資料。

## 構成

| ファイル | 役割 |
|---------|------|
| `part1/Upgrade.exe`, `part2/Upgrade.exe` | 同一バイナリ（204,800 byte, WinMM `midiOutLongMsg` で送信）。`images/Common.txt` の設定で挙動を変える |
| `part1/images/v200U12k.ydl` | 59,369 byte。ダウンローダ領域 0x000000–0x00BFFF（48KB）の更新データ |
| `part2/images/v200u22k.ydl` | 4,583,144 byte。本体ファーム 0x040000–0x3DFFFF（29 セクタ × 128KB） |

`.ydl` は Standard MIDI File（フォーマット 0, 96 tpqn, テンポ 120）で、先頭 4 バイトだけ `MThd` → `NZem` に差し替えてある。
中身は SysEx のみ。デルタタイムで送信間隔を制御している（バルクブロック間は 2 tick、セクタ消去後は約 1,176 tick 待つ）。

## ダウンロードモードへの入れ方（Common.txt より）

1. 電源を切る
2. **[Drum] + [PLAY] + [VALUE+] を同時に押しながら電源を入れる**
3. 更新失敗後は通常起動できず、自動的にダウンロードモードで立ち上がる（Readme より）

part1 は `download mode = manual`（ユーザーが手で入れる）、part2 は `auto`（part1 完了後は自動で DL モード）。

## 接続チェック

PC → MU2000 に何かを送り、MU2000 が次を返すと OK（Common.txt `check message`）:

```
F0 43 10 4C 06 00 00 "MU2000 Check      Connection OK!" F7
```

これは XG の Display Letter（43 10 4C 06 00 00）そのもので、LCD にこの文字列を表示させている。
つまり接続チェックは通常のファームで応答している。

## SysEx 一覧（モデル ID 0x59 = "MU128 DL" ダウンロードモード）

`n` はデバイス番号（送信 10、バルクデータは 00）。アドレス・サイズは 7bit × N バイトのビッグエンディアン。

| メッセージ | 意味 |
|-----------|------|
| `F0 43 10 59 00 7F 7F 7F 7F "MU128 DL" F7` | ダウンロードモード開始／識別 |
| `F0 43 10 59 0F "A0539MU128" F7` | 対象機種コード（MU128 系ダウンローダを MU2000 も共用） |
| `F0 43 10 59 00 02 04 00 00 0C 00 00 F7` | 不明（パラメータ設定。0x0C 00 00 = 0x30000?） |
| `F0 43 10 59 02 a a a a b b b b F7` | セクタ消去範囲: `00 10 00 00`→0x040000 から `01 7F 7F 7F`→0x3FFFFF。約 3 分半かかる（"DL Erase Sector" 表示） |
| `F0 43 10 59 01 a a a a F7` | 書き込み先セクタ選択（絶対アドレス, 128KB 単位） |
| `F0 43 00 59 02 r r r r <256B> ck F7` | 224 バイト書き込み。`r` はセクタ内相対アドレス。7bit 詰めは「データ 7 バイト + MSB 集約 1 バイト（末尾, bit6 が先頭バイトの MSB）」 |
| `F0 43 00 59 00 n r r r <n B> ck F7` | 端数書き込み（`n` = MIDI バイト数） |
| `F0 43 10 59 03 a a a a s s s 05 c c c F7` | セクタ書き込み完了。`s`=セクタサイズ 0x020000、`c`=チェックサム（3×7bit） |
| `F0 43 10 59 04 s s s 04 c c c F7` | part1 完了（サイズ 0x00C000 とチェックサム） |
| `F0 43 10 59 0E 02 <ck 6×7bit> F7` | 転送完了。`ck` = **フラッシュ 4MB 全体のバイト総和の下位 16bit**。実機は LCD に `DL Check Sum <hex>` と表示し、一致すれば OK、違えば NG（実機で確認、2026-09-05） |

各 SysEx のチェックサムは Yamaha 方式（デバイス番号以降〜チェックサム自身の総和 ≡ 0 mod 128）。全ブロックで検証済み。

## ソフトダンプへの含意

- ダウンローダ（0x000000–0x00BFFF、SH-2 コード。リセットベクタ PC=0x00000BD4）は USB 経由の SysEx で任意アドレスの Flash を書ける。
  **RAM への書き込みや任意コード実行コマンドがあるか**は、このダウンローダを逆アセンブルして確認する必要がある。
- ダウンローダ自体も part1 で書き換え可能なので、原理的には「波形 ROM を読んで送り返す」機能を持つ独自ダウンローダに
  差し替えられる。ただし失敗すると復旧手段が無くなる（純正ダウンローダを先に完全に保存しておくこと）。
- より安全な代替: 本体ファーム側（0x040000 以降）のどこかに読み出し機能を追加し、SysEx で起動する。
  ダウンローダは無傷なので、失敗しても純正アップデータで元に戻せる。
- 解析は MAME 上で `mu2000` を起動し（波形 ROM はダミーで可）、デバッガで行える。


## ダウンローダの逆アセンブル結果（2026-09-05）

`roms/mu2000_flash.bin` の 0x000000-0x00C001 がダウンローダ本体（SH-2、リセットベクタ PC=0x00000BD4）。

### コマンドディスパッチャ（0x0024A0-0x002522）

受信した SysEx のコマンドバイトを順に比較しているだけで、**存在するコマンドは 7 個のみ**。

| アドレス | 比較 | 分岐先 |
|---------|------|-------|
| 0x0024A6 | `CMP/EQ #$00` | 0x0024C8 |
| 0x0024AC | `CMP/EQ #$01` | 0x0024CE |
| 0x0024B0 | `CMP/EQ #$02` | 0x0024DE |
| 0x0024B4 | `CMP/EQ #$03` | 0x0024EC |
| 0x0024B8 | `CMP/EQ #$04` | 0x0024FA |
| 0x0024BC | `CMP/EQ #$0E` | 0x002500 |
| 0x0024C0 | `CMP/EQ #$0F` | 0x002510 |
| それ以外 | — | 0x002522（エラー） |

これは公式アップデータが使うコマンドと完全に一致する。**隠しコマンドは無く、任意アドレスへのジャンプや
RAM 実行のコマンドは存在しない**。

SysEx ヘッダ `43 00 59` / `43 10 59` は 32bit 定数 0x00430059 / 0x00431059 として
0x00246C, 0x002470 の literal pool に置かれている（バイト単位の検索では見つからない）。

### LCD メッセージテーブル（0x003418 起点, 0x28 刻み）

`DL HardwareReady` / `Get SRAM Area Top Adrs` / `Set Base Adrs Address` / `Erase Sector` /
`Write Data` / `Check Sum` / `Download Address` / `Replace All`。
ディスパッチャは状態番号を構造体オフセット 0x19 に書き、それがこのテーブルの添字になる。

### SRAM バッファ（0x003720-0x003733）

`0x00401580, 0x00401960, 0x00401C40, 0x00401F20, 0x00402200` の 5 個。
CPU のワーク RAM（0x400000-0x43FFFF）内にあり、受信データを一旦ここに溜めてから Flash に書く。

### 結論: ソフトダンプには自作ファームウェアが必要

隠しコマンドが無いので、「純正ファームのまま SysEx で吸い出す」ことはできない。
波形 ROM を読むには自作コードを実機で走らせる必要があり、そのためには Flash を書き換えるしかない。

## 波形 ROM の読み出し手段（SWP30 wave direct access）

`swp30.cpp` の 116-123 行目に、CPU から波形 ROM を直接読むレジスタが記載されている。
コントロールレジスタはチャンネルスロット 0x0E / 0x0F として現れる。

| レジスタ | 内容 |
|---------|------|
| ctrl 0x04 / 0x05 | wave direct access address（32bit を上位/下位 16bit で） |
| ctrl 0x06 / 0x07 | wave direct access size |
| ctrl 0x08 | トリガ（0x8000 = ROM から読む、0x9000 = RAM から読む、0x5000 = RAM へ書く） |
| ctrl 0x08(0x0F側) | ステータス |
| ctrl 0x0A / 0x0B | データ |

MU2000 では SWP30 マスターが CPU アドレス 0x800000-0x801FFF に見えている。
**この経路で波形 ROM 32MB 全体を CPU から読める**ことが確認できた。

## 安全な自作ファームウェアの方針

ダウンローダ（0x000000-0x00C001）は **絶対に書き換えない**。ここが生きている限り
[Drum]+[PLAY]+[VALUE+] 起動でダウンロードモードに入れ、純正アップデータでいつでも復旧できる
（実機で動作確認済み、2026-09-05）。

書き換えるのは part2 が扱う本体ファーム領域（0x040000-0x3DFFFF）のみ。手順:

1. 自作 SH-2 コードを書く（SWP30 経由で波形 ROM を読み、SCI0/1 の MIDI OUT か USB へ出す）
2. `tools/dump/ydl_extract.py` の逆処理で part2 形式の `.ydl` を生成する
3. **MAME 上で先に検証する**（ダウンローダも MAME でエミュレートされている。波形 ROM はダミーなので
   データは全 0 になるが、転送機構の検証はできる）
4. 実機に流す。失敗しても本体ファームが壊れるだけで、ダウンロードモードは無傷 → 純正アップデータで復旧


## コマンド 0x0E（転送完了）の解明

当初は意味が分からず公式ファイルからバイト単位で流用していたが、実機で NG になったことで判明した。

- 純正ファームを書いたときの期待値: `0x2762`
- 自作ダンパを書いた実機が計算した値: `0x1FB0`

`sum(4MB イメージ全体) & 0xFFFF` を計算すると、純正イメージで `0x2762`、
自作イメージで `0x1FB0` となり両方一致した。**ダウンローダ領域（0x000000-0x03FFFF）も含む
4MB 全体**が対象で、part2 が書き換えない領域も計算に入る。

メッセージ中では `02` の後ろに 6 個の 7bit 値として入る（純正は `00 00 00 00 4E 62`）。

副次的な収穫として、実機が計算した値が手元のイメージから計算した値と完全に一致したことで、
**アップデータから復元した 4MB イメージが実機のフラッシュと 1 バイトも違わない**ことが裏付けられた。

### NG になっても壊れない

チェックサムが NG でも各セクタの書き込み自体は完了しており、電源投入後は
本体ファーム（= 自作ダンパ）が正常に起動した。NG はアップデータへの報告のみで、
起動可否には影響しないことが実機で確認できた。

## 転送モードと受信経路（2026-09-06 に判明）

ダウンローダはワーク RAM 0x401049 の 1 バイトを転送モードとして持つ。
0x000EB4 の分岐で、モードが 2（USB）のときだけ SCI の割り込み優先度
（0xFFFF8352）を 0 にする。それ以外は 0x0D を入れる。

```
0eb4: CMP/EQ #$02,R0      ; モード 2 = USB か
0eb6: BF     0x0EC2
0eb8: R2 = 0 ; word @0xFFFF8352 = 0      ; USB -> SCI 受信を止める
0ec2: R3 = 0x0D ; word @0xFFFF8352 = 0x0D ; MIDI/シリアル -> 受信を有効に
```

つまり **HOST SELECT が USB のとき、MIDI IN からの `.ydl` は受け付けない**。
`tools/dump/send_ydl.py` は一方通行で応答を見ないので、送信側の進捗だけが進んで
実際には何も書き込まれない、という状態になる。LCD の表示が変わらないことで気づける。

同じ分岐で BRR1（SCI1 = TO HOST シリアル）も切り替わる。
モード 1 のとき 0x16（38,400bps）、それ以外は 0x1B（31,250bps）。
