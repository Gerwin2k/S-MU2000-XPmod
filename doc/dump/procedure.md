# 実機での作業手順

> **2026-09-06 に完了済み。** 波形 ROM 4 本すべて MAME 登録の SHA1 と一致した。
> 以下は再実行するときの手順として残してある。結果は
> [doc/dump/softdump.md](softdump.md#吸い出し完了2026-09-06) を参照。

所要時間: 書き込み 15 分 + ダンプ 約 3.8 時間。

ケーブルは 2 本使う。1 本でも吸えるが、取りこぼしたブロックを次の周回（3.8 時間後）まで
待つことになる。2 本繋いでおくと、PC 側から「このブロックを今すぐ送れ」と要求できる。

| 向き | 用途 |
|------|------|
| MU2000 の MIDI OUT → PC の MIDI IN | 波形データ（必須） |
| PC の MIDI OUT → MU2000 の MIDI IN A | 再送要求（任意だが強く推奨） |

## 0. 事前確認

1. **ケーブルの疎通を先に確かめる**（書き込み前にやること）
   - MU2000 の MIDI OUT から PC の MIDI IN（Babyface 等）へ 5 ピンケーブルを接続
   - リアパネルの HOST SELECT を **MIDI** にする
   - PC で受信モニタを起動する

     ```bash
     python tools/dump/recv_dump.py --port "Babyface" --monitor
     ```

   - MU2000 で [UTIL] → DUMP → 何かのバルクダンプを実行する
   - モニタにバイト列が流れれば配線は正しい。Ctrl+C で止める

2. **（任意）MIDI IN 側の疎通確認**

   ここは飛ばしてよい。ダンパを書いた後で再送要求が効かなかったときの切り分け用。
   書き込みに 12 分かかるので、先に本番へ進んで、問題が出てから戻ってくるのが早い。

   `build/rxtest.ydl` は、受け取ったバイトをそのまま返すだけの試験ファームウェア。
   ダンパと同じ経路で MIDI IN A が生きているかを確認できる。
   書き込み手順は「1. ダンパファームウェアの書き込み」と同じ（送る `.ydl` を差し替えるだけ）。
   電源を入れると

   ```
   F0 43 7D 52 44 59 F7      ← "RDY"（起動した）
   ```

   が出る。ここで PC から何か送ると、1 バイトにつき

   ```
   F0 43 7D 45 <上位4bit> <下位4bit> F7
   ```

   が返る。返ってこない場合は SSR の値が周期的に流れてくるので、
   bit5（ORER）や bit4（FER）を見れば原因の見当がつく。

3. 大切なユーザーデータ（パフォーマンス、サンプル、シーケンス）は先に退避する。
   書き込みで本体設定は初期化される。

4. `roms/updater/x/mu2r1_uw/` に純正アップデータが展開してあることを確認する（復旧用）。

## 1. ダンパファームウェアの書き込み

書き込むのは本体ファーム領域（0x040000-0x3DFFFF）だけ。
ダウンローダ（0x000000-0x00C001）には触れないので、失敗しても復旧できる。

経路が 2 つある。**A を先に試し、ダメなら B**。

### A. USB 経由（純正 Upgrade.exe、約 12 分）

Yamaha の USB-MIDI ドライバが必要。純正プログラムなので確実。

1. Yamaha の USB-MIDI Driver V3.1.5 for Windows 10/11 (64-bit) を入れる
2. PC と MU2000 を USB で直結する（ハブは使わない）
3. HOST SELECT を **USB** にする
4. 電源を切り、**[Drum] + [PLAY] + [VALUE+] を押しながら電源投入** → ダウンロードモード
5. `build/upgrade_dumper/Upgrade.exe` を実行し、画面の指示に従う
6. 終わったら電源を切り、HOST SELECT を **MIDI** に戻す

### B. MIDI 経由（自作 send_ydl.py、約 24 分 + 消去 3 分半）

USB ドライバが不要で、HOST SELECT は MIDI のまま。ケーブルを差し替えて使う。

1. ケーブルを **PC の MIDI OUT → MU2000 の MIDI IN-A** に接続する
   （ダンプ時は逆向きに差し替える。ケーブル 1 本を使い回せる）
2. HOST SELECT は **MIDI** のまま。

   > **USB のままだと 1 バイトも書き込まれない。** ダウンローダは転送モードが USB のとき
   > SCI（MIDI）の割り込み優先度を 0 にして受信を止める（0x000EB4 の分岐）。
   > `send_ydl.py` は相手の返事を見ないので、何も届いていなくても進捗は進んでしまう。
   > **LCD が "DL Erase Sector" などに変わらなければ受信していない。**すぐ中断してよい
   > （消去も書き込みも起きていないので無傷）。
3. 電源を切り、**[Drum] + [PLAY] + [VALUE+] を押しながら電源投入**
4. **予行演習を推奨**: まず純正ファイルを送って経路が正しいことを確かめる。
   純正ファームを書き直すだけなので、成功しても何も変わらない

   ```bash
   python tools/dump/send_ydl.py --port "Babyface" roms/updater/x/mu2r1_uw/part2/images/v200u22k.ydl
   ```

   終わって電源を入れ直し、いつもどおり起動すれば経路は正しい
5. 本番。もう一度ダウンロードモードに入れてから

   ```bash
   python tools/dump/send_ydl.py --port "Babyface" build/dumper_v3.ydl
   ```

所要時間の見積もりは `--dry-run` で出せる。

### 共通の注意

- **転送中は絶対に電源を切らない**
- 消去に約 3 分半かかる。LCD が "DL Erase Sector" のまま止まって見えるが正常
- 中断してもダウンロードモードは生きている。純正 part2 を送り直せば戻る

## 2. ダンプ

1. 書き込みが終わったら電源を入れ直す
2. HOST SELECT を **MIDI** にし、ケーブルを繋ぐ
   - **MU2000 の MIDI OUT → PC の MIDI IN**（必須）
   - **PC の MIDI OUT → MU2000 の MIDI IN A**（再送要求を使う場合）
3. LCD はダウンローダの最後の表示のまま固まる。これは正常。ダンパは LCD を触らない
4. PC で受信を開始する

   ```bash
   python tools/dump/recv_dump.py --port "Babyface" --req-port "Babyface" --out roms/dump
   ```

   `--req-port` を省くと受信だけになる（ケーブル 1 本の場合）。

5. 約 3.8 時間、そのまま放置する。進捗はコンソールに出る
   - 途中で中断しても `roms/dump/wave.part` に保存され、再実行すると続きから集まる
   - 各ブロックには加算和が付いていて、合わないブロックは捨てられる。
     進捗行の「加算和 NG」が増え続けるようならケーブルかノイズを疑う
   - `--req-port` があれば、穴が残ったまま既取得のブロックが続いたときに
     欠けているブロックへ飛ばす。無い場合は次の周回で埋まるのを待つ
6. 全ブロック揃うと `xv364a0.ic49` など 4 ファイルが書き出される

音量は絞っておくこと。ダンパは SWP30 の音声出力を制御しないので、ノイズが出る可能性がある。

## 3. 照合

```bash
python tools/dump/verify_roms.py roms/dump
```

MAME 登録の SHA1 と一致すれば成功。一致しない場合は、
取りこぼしか、ダンプ中のビット化けを疑う。`wave.part` を消さずにもう一周回す。

## 4. 純正ファームウェアに戻す

1. MU2000 の電源を切る
2. [Drum] + [PLAY] + [VALUE+] を押しながら電源を入れる
3. `roms/updater/x/mu2r1_uw/part2/Upgrade.exe` を実行する
   - **part1 は実行しない**。part1 はダウンローダを書き換えるので、
     触らずに済むなら触らない方が安全
   - part2 だけで本体ファームは純正 v2.01（EX Revision1）に戻る
4. 起動して [EXIT] を押しながら電源投入 → "2000 EX Revision1" が出れば復旧完了

## トラブル時

| 症状 | 対処 |
|------|------|
| 最後に `DL Check Sum` が NG | 起動には影響しない。そのまま電源を入れ直せばダンパは動く。`.ydl` を作り直せば OK になる |
| 起動後に LCD が意味不明な表示のまま | 正常。ダンパは LCD を操作しない |
| 書き込み後、通常起動せずダウンロードモードのまま | 手順 4 で復旧できる |
| MIDI にデータが来ない | HOST SELECT が MIDI か、ケーブルの向き（MU2000 の OUT → PC の IN）を確認 |
| ブロックが虫食いのまま増えない | 受信側の取りこぼし。他の MIDI アプリを閉じる。`--req-port` を付けると穴を狙って回収できる |
| 「加算和 NG」ばかり出る | ケーブルかノイズ。ブロックは捨てられるのでデータは汚れないが、進まない |
| 再送要求が効かない（`--req-port` 付きでも順送りのまま） | MIDI OUT → MIDI IN A の向きと HOST SELECT を確認。`build/rxtest.ydl` で切り分ける |
| 書き込み中に電源が落ちた | ダウンロードモードで起動するはず。手順 4 で復旧 |
| `send_ydl.py` の進捗は進むのに LCD が変わらない | HOST SELECT が USB になっている。MIDI にして最初からやり直す |
