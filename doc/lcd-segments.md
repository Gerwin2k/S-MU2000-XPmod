# LCD の決まった形のセグメント

MU2000 の窓には、点の並び（ドットマトリクス）のほかに、**ゲームウォッチの
ように形の決まったセグメント**が入っている。パンのつまみ、リバーブの扇、
ノートシフトの 7 セグ、`MIC` や `BANK` の札などがそれで、点いたり消えたり
するだけのもの。

これがどう駆動されているかは資料が無いので、**測って割り出した**。

## どこに入っているか

**DDRAM の 23 桁目（両行）は絵ではない**。CGRAM に書かれた 2 文字が、
そのまま 64 個のオンオフのビットになっている。

* 列 A-D = 1 文字 5 点のうちの bit3・bit2・bit1・bit0
  （**bit4 はいつも消えている**）
* 行 0-15 = 上の行の 0-7 と、下の行の 0-7 をつないだもの

つまり `A0` は「行 0 の 23 桁目の bit3」。

楽器のかたちは 20-22 桁の 3 マス（15 点 × 16 点）で、23 桁目は入らない。

7 セグの名前は普通の呼び方（a が上、b が右上、c が右下、d が下、
e が左下、f が左上、g が真ん中）。

**C2 と D8 のどちらかが PLG モードのカーソル**で、もう片方が何なのかは
分からない。こちらの環境では PLG ボードを積んでいないので、どちらも
一度も点かなかった。

## 確かめ方

### 送り量の 8 段

`CC91`（リバーブ）、`CC93`（コーラス）を 0 から 127 まで振って、
どの行が点くかを数えた。バリエーションは既定ではインサーション接続なので、
`02 01 5A` に `01` を送ってシステム接続にしてから `CC94` を振る。

```
    0 -> ........      65 -> ...#####
    1 -> .......#      81 -> ..######
   17 -> ......##      97 -> .#######
   33 -> .....###     113 -> ########
   49 -> ....####     127 -> ########
```

3 つとも同じ境目（1 / 17 / 33 / 49 / 65 / 81 / 97 / 113）で 1 段ずつ増える。

### パンの 7 か所

`CC10` を振ると、D9-D15 のどれか 1 つだけが点く。
0-16 が L63-L43、22-32 が L42-L22、43-48 が L21-L01、64 が中央、
80 が R01-R21、96 が R22-R42、112 以上が R43-R63。

### ノートシフトの 7 セグ

XG のパートパラメータ `08 nn 08` に値を送って振る。
**中心は `0x40`**（XG の決まりの `0x28` ではない）。
`0x40` を送ると、何も送らないときとビットが完全に一致する。

| 送る値 | 表示 | 一の位で点った線 | 読み |
|---|---|---|---|
| `0x28`（40） | −24 | b c f g | 4 |
| `0x29`（41） | −23 | a b c d g | 3 |
| `0x2d`（45） | −19 | a b c d f g | 9 |
| `0x40`（64） | ＋0 | a b c d e f | 0 |

一の位が 4 → 3 → 9 → 0 と読めて、−24 −23 −19 0 の一の位に合う。
符号は、縦棒（A0）が点くと ＋、消えると −。横棒（B0）はいつも点いている。

十の位は a/d/e/g がひとまとめで 1 本のビット（A1）になっている。
十の位に出るのは空白・1・2 だけなので、f（B4）は使われない。

### 札とカーソル

`MIC` `LINE` `A1/A2` `1`-`32` `BANK` `PGM#` は**印刷ではなくセグメント**で、
消えることがある。既定では `MIC` と `A1/A2` と `1`-`32` と `PGM#` が点いていて、
`LINE` と `BANK` は消えている。

モードのカーソルは、GS リセット（`F0 41 10 42 12 40 00 7F 00 41 F7`）を
送ると B5 が消えて A4 が点く。XG に戻すと逆になる。

## VOL と EXP はどこにあったか

最初は「この 64 ビットに無い」と書いたが、**行 0 の 19 桁目にあった**。
レベルメータとまったく同じ形（`0x7f + 9a + b`）で、
**左の 2 点が VOL、右の 2 点が EXP**。

`CC7` と `CC11` を振って確かめた。

| CC7（EXP は 127） | コード | 読み | | CC11（VOL は 127） | コード | 読み |
|---|---|---|---|---|---|---|
| 0 | `0x87` | (0, 8) | | 0 | `0xc7` | (8, 0) |
| 16 | `0x90` | (1, 8) | | 32 | `0xc9` | (8, 2) |
| 64 | `0xab` | (4, 8) | | 64 | `0xcb` | (8, 4) |
| 127 | `0xcf` | (8, 8) | | 127 | `0xcf` | (8, 8) |

実機では 2 本が離れた場所に出るので、1 マスを左右に切り離して描いている。

これで 24 桁ぶんの割り振りが全部埋まった。

| | 行 0 | 行 1 |
|---|---|---|
| 0-16 | 上の面（メータ 9 桁 ＋ 文字 8 桁） | 同じ |
| 17-18 | 「01」 | 「A01」の 1-2 文字目 |
| 19 | **VOL と EXP のバー** | 「A01」の 3 文字目 |
| 20-22 | 楽器のかたち | 同じ（下半分） |
| 23 | 決まった形のセグメント 32 個 | 同じ（残り 32 個） |

## 下の面の横位置

実機を見て教わった対応。上の面のパート番号と縦に揃っている。

| もの | 位置 |
|---|---|
| VOL | 15 番と左揃え |
| EXP | 18 番と右揃え |
| REV | 24 番と右揃え |
| CHO | 25 番と左揃え |
| VAR | 28-29 番の中央 |
| 札「BANK」（左） | 3-4 番の下 |
| 札「PGM#」（左） | 11-12 番の下 |
| 札「BANK」（右） | 19-20 番の下 |
| 札「PGM#」（右） | 27-28 番の下 |
| カーソル バンク番号 | 楽器のかたちの 4-5 列目の上 |
| カーソル プログラム番号 | 楽器のかたちの 12-13 列目の上 |

`REV` `CHO` `VAR` の形は半円ではなく、**縦に細長い楕円を 8 枚重ねた**もの。
細長い Wi-Fi の印のように見える。

## MAME には無い

MAME の `mulcd` が持っているのは**点の並びと LED だけ**。
`mulcd.svg` に入っているのも 48 マス × 40 点の四角で、決まった形の
セグメントはひとつも無い。`set_lcd_size(4, 20)` と書いてあるが、
描かれているのは 2 行 × 24 桁ぶん（`000`-`017` と `028`-`03f`）で、
こちらの持ち方と同じ。
