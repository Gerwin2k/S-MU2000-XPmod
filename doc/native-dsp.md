# エフェクトを C++ で鳴らす軽量モード（試作）

**既定は切。** 実機の音が要るときは、今までどおり MEG（実機のエフェクト DSP）をそのまま回す。
ここで作ったのは「実機の再現より軽さが欲しい」場面のための**別物**で、同じ音にはならない。

```bash
build/render.exe <rom> 曲.mid out.wav 30 --native-fx        # エフェクトだけ C++（MEG も回る）
build/render.exe <rom> 曲.mid out.wav 30 --native-fx-full   # MEG を回さない（いちばん軽い）
build/gui.exe    <rom> --native-fx-full                     # 窓でも同じ
build/live.exe   <rom> --native-fx-full
```

プラグイン（VST3・CLAP・AU）は `%LOCALAPPDATA%\S-MU2000\plugin.ini` に書く。

```
native_fx=2
```

## 何をしているか

MU2000 のエフェクトは、SWP30 の中の MEG という DSP が 1 サンプルにつき 384 段の命令を回して作る。
軽量モードは、**ミキサから MEG への送りを横取りして、代わりに C++ のエフェクトを鳴らす**。

| 送り | MEG のレジスタ | ミキサの出力 |
|---|---|---|
| リバーブ | m24 / m25 | 10 |
| コーラス | m26 / m27 | 11 |
| バリエーション | m2c / m2d | 14 |
| インサーション 1 | m28 / m29 | 12 |
| 乾いた音 | m20 / m21 | 8 |

この対応は、送りを 0 と 127 にした曲を鳴らしてレジスタを比べ、実測で決めた（`tools` には入れていない
使い捨ての道具で調べた）。インサーション 2-4 はマスタ側の送りに現れないので、まだ手を付けていない。

`--native-fx-full` では、さらに **MEG の 384 段を回さない**。乾いた音（ミキサ出力 8）と C++ の
エフェクトを混ぜ、マスター EQ（5 帯）も C++ で掛けて DAC へ出す。

## 中身

| ファイル | 中身 |
|---|---|
| `src/dsp/util.h` | 遅延の線・1 次と双 2 次のフィルタ・LFO（正弦は表引き）・包絡線を追うもの |
| `src/dsp/reverb.h` | 前遅れ → 初期反射 → 8 本の遅延を Householder 行列で混ぜる網（FDN）。各段に減衰のローパスとハイパス |
| `src/dsp/blocks.h` | 初期反射／ゲート・ディレイ・コーラス/フランジャー/フェイザー・回転/トレモロ/パン・歪み・EQ・ワウ・コンプ/ゲート・ローファイ・マスター EQ |
| `src/dsp/fx_native.h` | 種類（MSB/LSB）から作りを選び、XG のパラメータを渡す |

種類の割り当ては `xg::fx_categories()` の分け方に合わせてある（リバーブ系 → 残響、ディレイ系 → ディレイ、
歪み系 → 歪み…）。パラメータは `xg/fx_params.h` の表を引いて、**表示の値をそのまま物理量として**使う
（`ReverbTime` の `2.1` は 2.1 秒、`LPF Cutoff` の `6.3k` は 6300Hz）。値は `mu2000::native_fx_update()` が
512 サンプルごとにワーク RAM から読み直す。

## 実機とどれだけ違うか

HALL 1・リバーブ送り 127 で、同じ曲を書き出して比べた（2026-09-18）。

| | 山の rms | 尾の rms（音を離して 0.4 秒後） | RT60 の目安 |
|---|---|---|---|
| MEG（実機の作り） | 1005 | 67 | 1.65 秒 |
| C++（`--native-fx-full`） | 1281 | 46 | 1.20 秒 |

乾いた音だけの曲では、MEG と C++ で rms が 753.6 対 753.1 と一致する（乾いた道の目盛りは実測で合わせた）。
残響は**尾が実機より短く、低い帯が弱い**。帯ごとの差は 125Hz で 6.6dB、500Hz で 4.4dB、8kHz で 2.3dB。

ほかの種類も、同じ曲（音を 0.5 秒鳴らす）で比べた。山は音が出ている間、尾は離してから 0.25 秒後。

| 種類 | | 山の rms | 尾の rms | 揺れの深さ |
|---|---|---|---|---|
| CHORUS 1（コーラス送り 127） | MEG | 1110 | 6.9 | 0.17 |
| | C++ | 1200 | 4.1 | 0.27 |
| DELAY LCR（バリエーション送り 127） | MEG | 803 | 428 | 0.19 |
| | C++ | 1056 | 244 | 0.13 |
| DISTORTION（インサーション 1） | MEG | 352 | 29 | 0.02 |
| | C++ | 440 | 32 | 0.01 |

**合っているところ**: 大きさはどれも 1〜3dB の差に収まる。歪みの尾（音を離したあとの残り）も近い。

**合っていないところ**:

* ディレイの尾が実機の半分ほど（戻す量の解釈が違う。実機は出ている音をまとめて戻しているらしく、
  こちらもそう変えて 200 → 244 まで近づけた）
* コーラスの揺れがこちらのほうが深い（0.27 対 0.17）
* 帯ごとに見ると、2kHz から上でこちらが 5〜10dB 小さいことが多い

## 速さ

dense（16 パート・60 音）を 10 秒ぶん書き出したときの実時間（Ryzen 7 9700X、1 スレッド）。

| | 実時間 | 1 サンプルあたりの内訳 |
|---|---|---|
| 既定（MEG） | 2.03〜2.11 秒 | CPU 2298ns / SWP30 マスタ 1919ns（うち MEG 503ns） |
| `--native-fx-full` | 1.81〜1.82 秒 | CPU 2292ns / SWP30 マスタ 1315ns（MEG 0ns） |

**軽くなるのは 1 割ほど**（10〜14%）。理由は、重さの内訳がこうなっているから。

* SH-2（firmware）を動かすぶん … 2.3µs（全体の半分以上）
* SWP30 の声を作るぶん … 1.4µs
* **MEG（エフェクト）… 0.5µs**

つまり **エフェクトを C++ に置き換えても、消えるのは 0.5µs だけ**で、残りはそのまま残る。
「ネイティブ DSP なら桁違いに軽い」という話は、firmware ごとやめて XG の処理を全部書き直した場合の話で、
それはこのプロジェクトとは別の作りになる。

`--native-fx`（MEG も回す）は、MEG のぶんが残るので**既定より少し重い**。音の比べ用。

### 測るときの注意

per-sample の道に `static const bool x = std::getenv(...)` のような**関数内 static を置くと、それだけで
1 サンプルあたり 1µs ほど遅くなる**（呼ぶたびに初期化済みかを確かめる）。調べもの用の切り替えを
入れたまま測って、「軽量モードのほうが 4 割遅い」という逆の結果を出しかけた。切り替えは外して測ること。

## まだ無いもの・分かっていないこと

* インサーション 2-4（マスタ側の送りに出てこない。スレーブの SWP30 かもしれない）
* バリエーションの接続が INSERTION のときの扱い
* コーラス・ディレイ・歪みなどの、実機との数字での比べ
* 種類ごとの細かい作り（XG の種類は 118 ある。いまは系統ごとに 1 つの作りを当てている）
* 状態の保存（`--native-fx` の中身は機械まるごとの状態に入らない）
