# 画面

`gui.exe` と VST3 の画面は**同じもの**（`src/ui/panel.*`）。GDI だけで描いていて、
外からは HDC を 1 枚渡すだけ。面が 2 つある。

```
make            gui.exe も一緒に作る
build/gui.exe <rom ディレクトリ> [--midi 番号] [--midiout 番号]
              [--latency ミリ秒] [--size 1400x360]
build/gui.exe --list                      MIDI の入口と出口の一覧
build/gui.exe <rom> --boot --shot 絵.png   窓を出さずに絵だけ書き出す
```

## MIDI の口を選ぶ

**動かしたまま画面から選べる**。パネルに描いてある `MIDI IN A` の
ジャックを左クリックするか、窓のどこかを右クリックすると品書きが出る。

| | 中身 |
|---|---|
| MIDI IN | ここから受けて鳴らす。Domino などを繋ぐ口（[doc/domino.md](domino.md)） |
| MIDI OUT | 受けたものを**そのまま外へ流す**。実機の THRU と同じ。画面のつまみから出たコントロールチェンジや SysEx も一緒に出るので、実機と聴き比べるのに使える |

選んだものは `%LOCALAPPDATA%\S-MU2000\gui.ini` に**名前で**覚える。
番号で覚えると、USB の機器を挿し直したときに別の機器へ繋がってしまう。
`--midi` / `--midiout` を付けたときはそちらが勝つ。

窓のいちばん下の行に、いま繋がっている口が出ている。

MIDI 出力の Windows の API は待たされることがあるので、**音声スレッド
からは呼ばない**。音声スレッドは輪っかにバイトを積むだけにして、
別のスレッドが取り出して送る（`src/ui/midi_out.*`）。

## パネルの面

実機のフロントパネル。**実機の写真から採寸して並べてある**
（左に A/D INPUT と VOLUME と電源、中央に LCD と音色カテゴリ 18 個、
右に PLAY/EDIT/UTIL/EFFECT/SAMPLING/SEQ の 6 個と 3×3 のボタン、そして大きなダイヤル）。

| もの | 中身 |
|---|---|
| LCD | 本物の HD44780。字の絵は `roms/hd44780u_b04.bin` から引く。**文字が 2 行 × 20 桁 ＋ 絵記号のセグメント部**（下記） |
| LED | PLAY / EDIT / UTIL / EFFECT / SAMPLING / SEQ の 6 個と、MU / PLG-1〜3 の 4 個。firmware が点けたとおり。6 個は押しボタンを兼ねている |
| ボタン | 35 個。MAME の `mu500` の入力ポートと同じ配線 |
| 大きなダイヤル | **ホイールで回す**。実機のロータリーエンコーダ（ポート A の bit17/16）をそのまま動かしている。VALUE −/+ と同じ働き（下記） |
| VOLUME | 音源の外で掛ける。VST3 では Output パラメータと同じ値 |

キーボードでも押せる（MAME の割り当てと同じ）。

```
A=PLAY  E=EDIT  U=UTIL  F=EFFECT  S=MUTE/SOLO  [ ]=PART−/+
−  ==VALUE−/+  BackSpace=EXIT  Enter=ENTER  , .=SELECT◀▶
Q=SEQ  Z=AUDITION  X=SELECT  M=SAMPLING/MODE
```

LCD には firmware が書いたものがそのまま出る。起動すると
`◀000▶001 GrandP #01` のような演奏画面になる。

### 窓の分かれ方

**DDRAM の桁が、そのまま横一列に並んでいるのではない**。
ボタンを押して、どの桁が何に化けるかを追いかけて割り出した。

| DDRAM | どこに出るか |
|---|---|
| 0-8（両行） | 上の面のレベルメータ。1 マス 2 本で 18 本（A1 A2 と 1-16） |
| 9-16（両行） | 上の面の文字 8 桁。1 行目が音色名、2 行目が `▶000◀001` |
| 行 0 の 17-18 | **下の面の左**。部の番号「01」 |
| 行 1 の 17-19 | **その右**。「A01」 |
| 20-23（両行） | **下の面**。楽器のかたち。両行で 1 枚の絵 |
| 行 0 の 19 | 不明。まだ何なのか分かっていない |

割り出し方は、PART+ を押して 17-18 桁が `01`→`02` と動くこと、
VALUE+ で 9-16 桁の音色名と 2 行目の番号だけが動くこと、
GS リセットを送ると 9-16 桁が `GrandP #`→`GrandPno` に変わること
（TG300B の音色名は 8 文字ぶん使う）を見て決めた。

上の面は **2 行のあいだに隙間が無い**。レベルメータのバーが上下の行に
またがって伸びるので、空けるとバーが切れてしまう。桁のあいだは 1 点あく。

下の面は上の面とは並びが違う。

* 「01」と「A01」は**塊の中の桁を詰めて**並べ、塊のあいだを 2 点あける
* そこから 3 点あけて楽器のかたち。**この区画だけ点が細かく、正方形でもない**。
  横 20 点・縦 16 点ぶんの絵が、文字 1 行ぶんの高さに詰め込まれている
* その右は VOL / EXP / PAN / REV / CHO / VAR / KEY のセグメント
* いちばん右に XG / TG300B / PERFORM を示す小さな `▶` が 3 つ

窓の下に印刷されている札は、この並びと同じ位置に置いてある。

### レベルメータと表示器

firmware は**左の 9 マス**にレベルメータを描いている。
**1 マスに 2 本**のバーが入っていて、**バーの幅は 2 ドット**。
文字コードは

```
0x7f + 9 × 左のバーの点の数 + 右のバーの点の数     （どちらも 0-8）
```

上の行と下の行で**同じ表**を使う。バーは 2 行にまたがって伸びるので、
下の行が 8 まで埋まってから上の行が 1 から伸びていく。上の行まで届いて
いない側は 0。両方 0 のマスには空白 (`0x20`) が入る。

鳴っていないパートも 1 点だけ出る（左右とも 1、コード `0x89`）。
窓の下に点が 1 列並んで見えるのはこれ。

9 マス × 2 本 = 18 本で `A1 A2 1 2 … 16`。マスの左半分がパート 1・3・5…、
右半分がパート 2・4・6… に当たる。**表示の仕方によっては、右半分に
チャンネル B（17-32 トラック）の音量が出る**。

#### どうやって割り出したか

この LCD の字の絵は手に入らないので、firmware が書くコードを測った。
パート 1 とパート 2 だけを鳴らし、CC7 を 0 から 127 まで振って
DDRAM を読む。

| パート 1 | パート 2 | 上の行 | 下の行 | 読み方 |
|---|---|---|---|---|
| 0 | 0 | `20` | `89` | (1,1) 両方 1 点 |
| 48 | 0 | `20` | `bf` | (7,1) |
| 0 | 48 | `20` | `8f` | (1,7) |
| 48 | 48 | `20` | `c5` | (7,7) |
| 127 | 0 | `c7` | `cf` | 下 (8,8)、上 (8,0) |
| 127 | 64 | `c8` | `cf` | 上 (8,1) |
| 127 | 127 | `cf` | `cf` | 上下とも (8,8) |
| 16 | 127 | `87` | `a2` | 下 (3,8)、上 (0,8) |

左右がきれいに足し合わさり、上の行にも同じ表が使われていることが読める。
`0x80`-`0x88` も同じ表の一部（左が 0、右が 1-8）で、以前**幅いっぱいの
1 本バー**だと思っていたのは間違い。基準も `0x89` ではなく `0x7f` で、
バーが 1 点ずつ低く出ていた。

字の絵は本来 CGROM に入っているが、こちらが持っているのは ASCII だけの
代用フォントなので、**上の規則から起こしている**。本物の CGROM
（MAME の `mulcd.zip` の `hd44780u_b04.bin`）を置けばそちらが優先される。

パン／リバーブなどの表示器は右端の 2 行 × 4 マスにあり、こちらは
**firmware が CGRAM に書いた絵**なので最初から本物が出る。

見るには曲を流しながら絵を書き出す。

```
build/gui.exe roms --mid song.mid 60 --shot panel.png --size 2200x880
```

### ダイヤルと VALUE −/+ は同じもの

実機では大きなダイヤルと VALUE −/+ のボタンは同じ働きをする。
入り口はまったく別（ダイヤルはポート A、ボタンはスイッチの格子）だが、
firmware の中で同じところに落ちる。実測でも一致した。

| したこと | Volume の値 |
|---|---|
| 何もしない | 100 |
| VALUE+ を 3 回叩く | 103 |
| ダイヤルを +3 目盛り | 103 |
| ダイヤルを +1 目盛り | 101 |

長押しの連打も firmware 自身がやる（0.3 秒で +1、1 秒で +5、2 秒で +18 と加速）。
こちらは実機のスイッチをそのまま押しているだけなので、何も作り込んでいない。

画面でもそう扱う。**ホイールはどの面でもダイヤルとして効き**、
VALUE −/+ を押すとダイヤルの絵も一緒に回る。

### ダイヤルの中身

MAME はここを動かしていない（`pa_r()` が 0xffff を返すだけ）。配線の
覚え書きだけが残っていたので、実測で決まりを出した。

  * firmware は 2.5ms ごと（400Hz）にポート A を読む
  * **bit17 の立ち上がりで 1 目盛り、bit16 を立てておくと逆向き**
  * 素直な直交位相ではない
  * `0xffff` には bit16/17 が入っていない。MAME が返していた値は
    「ダイヤルが止まっている」に当たる

## エディタの面

SOL2 の XG エディタに倣った面。パートを 1 つ選び、そのパートのつまみを動かす。

**音源には手を入れていない。MIDI を送っているだけ**。つまみはすべて XG の
コントロールチェンジで決まっているものなので、実機に送るのと同じことをしている。
だからパネルから触った結果とも矛盾しない。

| 段 | つまみ |
|---|---|
| 1 | Volume(7) / Pan(10) / Expression(11) / Reverb(91) / Chorus(93) / Variation(94) |
| 2 | Cutoff(74) / Resonance(71) / Attack(73) / Decay(75) / Release(72) / Vib Rate(76) |
| 3 | Vib Depth(77) / Vib Delay(78) / Porta(5) / Modulation(1) / Bank(0) / Program |

つまみは上下にドラッグ、またはホイール。`XG リセット` は XG システムオン
（`F0 43 10 4C 00 00 7E 00 F7`）を送る。

覚えている値は「この画面から送った値」。音源から読み返す術が無いので、
パネル側で音を変えると表示とずれる。SOL2 のエディタも同じ立て付け。

### 効いていることの確かめ方

エディタで Program を 19 にしてからパネルの面に戻ると、LCD が
`◀000▶019 RockOrg#01` に変わる。画面 → bridge → 音源 → firmware → LCD と
一周しているのが目で見える。

## エフェクトの面

リバーブ／コーラス／バリエーション（XG のシステム側）と、
MU2000 の**インサーション 2 系統**。番地は実測で確かめたもので、
一覧と確かめ方は [doc/effects.md](effects.md)。

種別は `<` `>` で選ぶか、ホイールを回す。「この画面を送り直す」を押すと
画面の値を全部送り直せる。

## 中の作り

```
ui::panel     配置・描画・当たり判定。面の切り替えもここ
ui::bridge    画面と音源のあいだ。ボタンは atomic のビット、
              MIDI は輪、LCD の写しは seqlock。錠は使わない
ui::driver    音声スレッド側。ボタンを音源へ、MIDI を音源へ、写しを画面へ
```

音源は音声スレッドが回しているので、画面から直接触ってはいけない。
触れ合うのは bridge だけ。

## 窓を出さずに見た目を直す

`--shot` で PNG に書き出せる。窓を開けない場所（自動での確認、不具合の報告）で使う。

```
build/gui.exe roms --boot --shot panel.png --size 1400x360
```
